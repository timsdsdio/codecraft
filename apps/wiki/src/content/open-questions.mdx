Each page has its own design questions in pink boxes. These are the ones that affect more than one page.

## 1. Look and feel

The aim is Create's UX in a dark, neon look. The machines come in two material sets, and the **TRON / BRASS** switch in the top bar flips every 3D view on the wiki between them:

- **Tron** (default): dark bodies, glowing neon edges, cyan floor grids.
- **Brass**: Create-style brass, copper and andesite, with the same neon fluids.

Pick one by looking at both, or mix them, for example Tron structure with brass only on moving parts.

"Create UX" mostly means interaction patterns rather than art: Jade-style tooltips ([[Inspecting]]), [[Engineer's Goggles]] for extra detail, and **Ponder**. Create's Ponder scenes are small animated dioramas that explain one mechanism each, and they're essentially what this wiki's 3D figures already are. A Ponder-style "explain this" view for any machine in the game could reuse them.

## 3. Which hooks get machines?

Only `useState` / `useReducer` ([[State Tank]]) in the first version. Candidates for later: `useMemo` (a hopper that refills only when its inputs change), `useRef` (a locked crate), `useEffect` (fires after the [[Display Link]]).

## 4. Slow motion

Should there be a mode that queues commits and plays them one at a time, with step controls? See [[Render]] and [[Update Replay]].

## 5. Settled so far

Decisions already made while writing these pages, with reasons. Push back on any of them:

- **Floors are tree depth, with the root at the bottom** ([[Floors]]). Each machine sits under what it draws, and nothing overlaps.
- **Jump goes up one floor, not straight to the screen** ([[Player]]). This keeps you oriented in a deep tree; <Key>Home</Key> goes straight up.
- **Scrolling is clipping** ([[Fold]]). It's cheap, exact, and needs no special-case physics.
- **The app runs unmodified in an iframe** ([[Screen Rendering]]), and is read with the DevTools hook ([[Probe]]).
- **One pipe per child, carrying all its props**, rather than one per prop ([[Pipe]]). This keeps the factory readable.
- **Function props are wires running downward, not pipes** ([[Event Wire]]). They're the only thing that flows the other way.
- **No server for now.** The first version is a local-only, single-player visualizer. `docs/STACK.md` comes back into play for Electric-synced todos (data entering from below the ground) or multiplayer visits.
- **Context is wireless** ([[Wireless Access Point]]). Range is the provider's footprint column, which is exactly the set of possible consumers.
