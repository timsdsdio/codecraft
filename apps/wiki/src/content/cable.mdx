A **cable** joins a [[Block|block's]] output to another block's input. It is the only way one block can reach another. Cables are run with the [[Wire Coil]] and cut with the [[Wire Cutters]].

## Rules

A cable can join two [[Socket|sockets]] when:

1. Both belong to the same [[Interface]] id.
2. One is an output and the other is an input.
3. They're on different blocks.
4. It wouldn't create a loop.
5. The same cable doesn't already exist.

If the input already holds its one cable, the new cable replaces it. A cable can't pass through the [[Network Wall]]; only a link block can carry it across.

## Appearance

A cable leaves each socket straight out along the face, then sags in a gentle arc. It takes the colour of its interface. Dashes flow along it from the provider to the consumer, so you can always tell which way it runs.

Thickness shows the interface's kind: thin for values, medium for views, thick for network cables.

## Pulses

Each call along a cable sends a bright flash from the provider to the consumer. On a network cable the response flashes back the other way, so you can watch a request cross the wall and return. Pulses are drawn in the shader, so a busy cable costs nothing extra to show.

## Network cables

A network cable is one interface with two halves, `:handler` and `:remote`. The server provides the handler. A link block takes the handler and provides the remote. Client blocks take the remote. Because the ids differ, you can't plug a client straight into a server: there has to be a link in between. See [[Mock Link]].

Every method on a network cable takes one JSON object and returns a promise of JSON. That's the shape of any RPC, so the contract doesn't change when the link becomes a real network ([[HTTP Link]]).
