A **block** is one piece of a program, standing in the world as a glowing glass cube. A block knows only the [[Interface|interfaces]] it declares. It has no other way to reach the rest of the program: everything it needs arrives through its input [[Socket|sockets]], and everything it offers leaves through its output sockets.

## Appearance

Blocks are dark glass with bright edges. The edge colour comes from the block's [[Zone]]: cyan for client, amber for server, magenta for link. A wireframe core turns inside the cube. It spins faster while the block is part of the running app.

A block that is part of the running app is **active** and drawn bright. A block that nothing on the [[Monitor]] depends on is **idle** and drawn dim. An idle block costs nothing and can never cause an error (see [[Composition]]).

## Faces

Sockets sit on faces according to which way data flows. +Z is the front, the direction of the monitor:

- **Front**: outputs (things this block provides). Male plugs.
- **Back**: inputs (things this block needs). Female sockets.
- **Top**: view inputs, the slots where child components plug in. A list's row view plugs into the top of the list, so children stack on their parents like bricks.

Because outputs face forward and inputs face back, cables always run toward the monitor. Reading the room from front to back follows the dependency graph from the screen down to storage.

## Moving blocks

Pick a block up with the [[Wrench]] and set it down on the floor cell you're aiming at. A block stays inside its zone, snapped to a half-metre grid. Moving a block never changes what it's connected to.
