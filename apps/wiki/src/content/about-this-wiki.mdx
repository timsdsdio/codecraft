This wiki is the design document for CodeCraft. It's written as a game wiki so that every idea gets described the way a player would meet it: a block, what it connects to, what it does, how you use it.

## Workflow

1. Write or change a page.
2. Discuss it, and change it again. Many rounds are expected.
3. Once a page is agreed, set its status to `settled`.
4. Build it. Anything the build does differently from the page goes in `DEVIATIONS.md`, and the page is updated to match.

## Writing pages

Pages are MDX files in `apps/wiki/src/content/`. The file name is the page's address: `wire-coil.mdx` is `/wiki/wire-coil`. Each file starts with frontmatter:

```yaml
---
title: Wire Coil
category: Tools          # Concepts, Blocks, Tools, Mechanics, Gameplay, Meta
summary: One line for search and category lists.
status: prototype        # prototype | draft | open | settled
aliases: [Coil]          # other names that link here
infobox:
  tool: wire             # or `block: todo-service`, or `scene: monitor`
  rows: { Use on: "Socket, then a matching socket" }
---
```

Link to another page with `[[Page name]]` or `[[Page name|link text]]`. A link to a page that doesn't exist shows up red. Inside a table, write the pipe as `\|`.

## 3D views

The 3D views use the same components the game will use, from `packages/visuals`. A page can drop one in anywhere:

| Component | Shows |
|---|---|
| `<BlockFigure id="todo-service" />` | one block, with its port names |
| `<SceneFigure name="link" />` | a small named scene, defined in `embeds/scenes.tsx` |
| `<ToolFigure tool="wire" />` | a hand tool |

Each one takes `caption`, `float` (`right`, `left`, `wide`, `none`), `width` and `height`. Blocks and interfaces are defined once in `apps/wiki/src/data/catalog.ts`, so a block looks the same on every page.

A view only starts its 3D renderer while it is near the screen. Until then, and if WebGL isn't available, it shows a flat placeholder.

## Other helpers

- `<Iface id="core.Clock@1" />`: an interface id with its socket swatch.
- `<Question>…</Question>`: a highlighted unresolved design question.
- `<Key>E</Key>`: a key cap.
- `<InterfaceTable />` and `<BlockTable />`: tables generated from the catalog.
